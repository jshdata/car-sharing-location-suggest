# 카셰어링 차고지 입지 추천

인구·교통·주차장 등 공간 데이터를 분석하고, P-median 알고리즘을 활용해 카셰어링 차고지 후보지를 비교하는 데이터 분석 프로젝트입니다.

## 프로젝트 배경

카셰어링은 앱으로 차량을 예약해 필요한 시간만 이용할 수 있지만, 원하는 곳에서 차량을 찾고 반납할 수 있는 차고지의 위치가 이용 편의에 영향을 줍니다. 이 프로젝트는 인구·교통·관광·상권·주차 데이터를 바탕으로 대전광역시의 기존 공영주차장 등을 후보지로 삼아 차고지 입지를 비교하는 분석입니다.

프로젝트 발표자료에는 208명 설문 결과로 응답자의 56.7%가 카셰어링 이용 경험이 있고, 카셰어링 이용 운전자 중 약 31.4%가 차고지 부족을 불편 요인으로 답했다고 정리되어 있습니다. 이는 프로젝트에서 추가 차고지의 필요성을 검토한 배경 자료이며, 전체 운전자나 현재 시장을 대표하는 조사로 일반화하지 않습니다.

초기 지역 비교에서는 17개 시도의 인구 대비 차고지 현황, 관광지, 승용차 교통량, 20~30대 인구 등을 순위 점수화했습니다. 발표자료 기준 서울과 대전은 각각 52점, 인천은 49점이었고, 서울의 기존 차고지 집중도와 운영 비용에 대한 우려 등을 고려해 대전을 분석 대상 지역으로 선택했습니다. 이 점수와 지역 선정은 프로젝트 당시 사용한 비교 기준과 가설이며, 시장 포화나 실제 수요를 별도로 검증한 결과는 아닙니다.

## 분석 흐름

1. 지역별 인구, 차량·교통량, 교통 인프라와 차고지 현황 탐색
2. 대전광역시를 **500m × 500m 격자**로 나누고 공간 데이터를 격자 단위로 가공
3. 다섯 지표에 맞춰 변수의 방향을 정리하고 등간격 구간화로 점수화
4. 공영주차장 등의 후보지를 대상으로 P-median 조합 비교
5. 후보지별 가중 거리와 지표 점수를 지도 및 차트로 시각화

### 점수화 기준

발표자료는 이를 점수 스케일링(Scaling)이라 설명하며, 변수별 값을 데이터 분포와 관계없이 5개의 동일 폭 구간으로 나눠 1~5점으로 변환하고 0값은 점수 분포에서 제외합니다. 보존된 `점수별 범주화.ipynb`에서도 `pd.cut`으로 5개 구간을 만들고 일반 변수는 낮은 구간부터 1점, 높은 구간부터 5점을 부여합니다. 노트북에서 역방향으로 지정한 시내버스정류장·도시철도·차고지 변수는 반대로 낮은 구간에 5점, 높은 구간에 1점을 줍니다. 이후 원인 변수 점수의 평균으로 적합성·수요성·통행량·가용성·활동성 지표를 구성합니다.

해당 노트북은 0을 범주화 전에 결측값으로 바꾸고, 뒤에서 결측값을 0으로 채우는 코드도 포함합니다. 프로젝트 회고에 기록된 0값 점수화 오류와 재작업 이력이 있으므로, 이 설명은 저장소에 남은 노트북의 한 버전이며 최종 적용 기준이라고 단정할 수 없습니다. 점수화 입력 CSV와 최종 실행 결과가 없어 실제 최종 구간 경계, 결측·0 처리 및 각 변수 방향의 적용 여부는 확인되지 않았습니다.

### 지표와 가중치

| 지표 | 프로젝트에서 고려한 요인 | 발표자료의 가중치* |
| --- | --- | ---: |
| 적합성 | 대중교통·숙박시설 접근성 | 0.28 |
| 수요성 | 20~30대 인구, 관광지와 숙박시설 간 거리 | 0.21 |
| 통행량 | 승용차 교통량 | 0.20 |
| 가용성 | 기존 차고지 분포, 공영주차장·주차구획 | 0.15 |
| 활동성 | 상권 매출, 20~30대 유동인구 | 0.15 |

* 가중치는 변동성을 바탕으로 산정했습니다. 표의 값은 발표자료에 표시된 반올림 값이므로 합계가 0.99입니다.

#### 가중치 산정 공식

발표자료의 변동성 기반 방식은 각 지표 점수의 표준편차 역수를 구한 뒤, 역수의 합으로 나누어 가중치를 정규화합니다. 따라서 변동성이 작은 지표일수록 큰 가중치를 받습니다.

$$
w_j = \frac{1/\sigma_j}{\sum_{k=1}^{m}(1/\sigma_k)}
$$

여기서 $w_j$는 지표 $j$의 가중치, $\sigma_j$는 해당 지표 점수의 표준편차, $m$은 지표 수입니다. 발표자료의 반올림 전 값은 적합성 0.282625, 수요성 0.212695, 통행량 0.202091, 가용성 0.151681, 활동성 0.150908이며, 표에는 이를 소수 둘째 자리로 반올림해 표시했습니다.

#### 가중합법

가중합법(Weighted Sum Method)은 여러 평가기준의 점수에 기준별 가중치를 곱해 더하여 종합 점수를 계산하는 다기준 의사결정 방법입니다.

$$
\mathrm{Score} = \sum_{j=1}^{m} w_j v_j
$$

여기서 $v_j$는 기준 $j$의 평가값, $w_j$는 그 기준의 가중치입니다. 이 프로젝트에서는 지표별 점수와 발표자료의 가중치를 결합해 종합 평가에 반영하며, P-median 비교에서는 여기에 각 격자에서 가까운 후보지까지의 거리를 곱해 후보 조합의 목적값을 구성합니다.

### P-median 비교와 결과

P-median은 수요 지점과 후보 시설 사이의 거리 합을 줄이도록, 정해진 수 P개의 시설 위치를 선택하는 입지 최적화 방법입니다. 이 프로젝트에서는 새 부지를 조성하는 대신 공영주차장이 포함된 격자를 차고지 후보지로 설정했습니다. 각 500m × 500m 격자의 중심점을 기준으로 격자 간 유클리드 거리를 계산하고, 각 격자에서 가장 가까운 후보지까지의 거리를 구했습니다. 격자 i의 지표 j 점수를 $s_{ij}$, 발표자료의 해당 지표 가중치를 $w_j$, 격자 i에서 가장 가까운 선택 후보지까지의 거리를 $d_i$라 하면, 프로젝트에서 비교한 목적값은 다음과 같이 표현할 수 있습니다.

$$
\min_{S,\ |S|=P}\ \sum_{i=1}^{n}\sum_{j=1}^{m} w_j s_{ij} d_i(S),
\qquad d_i(S)=\min_{q\in S}d(i,q)
$$

즉 후보 조합의 목적값이 작을수록 지표별 점수와 가중치로 반영한 격자-후보지 거리 합이 작습니다. 점수가 큰 격자는 목적값에 더 큰 영향을 주므로, 같은 P에서 그런 격자와 가까운 후보 조합이 유리해질 수 있습니다. 목적값은 후보지 조합을 비교하는 거리 기반 지표이지, 개별 후보지의 적합도 점수나 실제 이용량·수요 예측값은 아닙니다. 후보지 수 P=1, 2, 3일 때의 배치를 살펴봤으며, 발표자료는 후보지 지도와 지표별 레이더 차트를 제공하고 웹 화면에서 후보 결과의 상위 10%와 하위 10%를 비교하는 구성을 소개합니다.

발표자료의 가중치는 변동성을 바탕으로 산정한 뒤 반올림한 값으로 표기되어 합계가 0.99입니다. 거리 계산은 저장된 노트북에서 EPSG:4326 경위도 좌표를 그대로 유클리드 식에 넣는 방식이므로, 계산값을 미터 단위의 실제 거리로 해석할 수 없습니다. 이 결과는 프로젝트에서 구성한 지표·가중치·거리 계산에 따른 후보 비교이며, 실제 차량 이용량, 운영 비용, 도로망 이동시간이나 차고지 운영 성과를 이용한 현장 검증 결과가 아닙니다.

### 분석 회고와 한계

- 초기 점수화 실험에서 부정 방향 지표를 역순으로 바꿀 때 0값을 별도로 처리하지 않아, 0이 불리한 점수로 매핑되는 문제가 있었습니다. 문제를 발견한 뒤 전처리를 다시 검토했습니다. 아카이브에는 여러 실험이 함께 있으므로 노트북별 최종 적용 여부는 셀과 결과를 확인해야 합니다.
- 인구 지표는 20~30대 분포와 아파트 주거단지에 집중되는 다른 연령대의 분포가 섞일 수 있습니다. 회고에서 주거 형태를 분리해 고려할 필요를 확인했으며, 현존 데이터로 그 효과가 보정되었다고 단정하지 않습니다.
- 당시 후보 격자 276개에서 계산량 때문에 P=4, 5 비교를 충분히 수행하지 못했습니다. 후보 수를 늘리기 전에 알고리즘 구현과 병렬 계산 등을 최적화하는 것이 후속 과제입니다.
- 발표자료의 반올림 가중치와 보존된 `p_median 알고리즘.ipynb`의 가중치 값이 서로 다릅니다. 보존된 `가중치.ipynb`에는 표준편차를 정규화하는 셀과 역수를 정규화하는 셀이 모두 있지만, 입력 CSV와 실행 결과가 없어 발표자료의 역표준편차 방식 및 0값 제외 처리가 실제 산정에 적용됐는지 확인할 수 없습니다. README는 발표자료에 기재된 역표준편차 방식과 가중치를 기준으로 설명하며, 당시 실행 결과를 그대로 재현할 수 있다고 보장하지 않습니다.
- 거리 계산을 개선하려면 격자 중심점 좌표를 대전 지역에 적합한 미터 단위 투영 좌표계로 변환해 직선거리를 다시 계산하고, 실제 접근성을 평가할 때는 도로망 이동거리나 이동시간도 별도로 비교해야 합니다. 개선된 거리 기준으로 P=1, 2, 3의 목적값과 후보 순위가 어떻게 달라지는지 기존 결과와 대조하는 것이 후속 과제이며, 아직 수행된 작업은 아닙니다.
- 전국 단위 확대와 실제 이용 데이터를 이용한 수요·운영 성과 검증은 향후 발전 방향으로 제시된 내용이며, 완료된 기능이 아닙니다.

## 추가 수집·가공 자료

원본 ZIP에서 카셰어링 폴더와 같은 수준에 있던 `코드/`, `크롤링/`도 프로젝트 자료로 포함했습니다. 하위 폴더 구조와 참고 문서를 유지하고, 중첩 Git 이력·체크포인트·캐시는 제외했습니다. 인증정보로 보이는 코드의 문자열은 `YOUR_CREDENTIAL_HERE`로 대체했으며, 사용 시 본인의 인증정보를 별도로 설정해야 합니다.

`크롤링/SoftCar/`에는 원본에 포함된 서비스 참고 코드와 환경 파일이 있습니다. 분석 노트북과 별도의 실행 환경을 사용하며, 참고 코드의 작성 주체나 라이선스를 새로 주장하지 않습니다. 수집 코드와 서비스 코드는 실행 검증하지 않았습니다.

100 MB를 넘는 원본 여행조사 Excel 파일은 Git LFS로 관리합니다. 전체 파일을 받으려면 Git LFS를 설치한 뒤 `git lfs pull`을 실행해 주세요.
